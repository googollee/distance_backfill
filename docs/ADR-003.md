# ADR-003：后台自动补全改为可选开关

## 状态

已采纳

## 背景

参见 [PRD-001](./PRD-001.md) 功能需求3"触发方式"、[ADR-001](./ADR-001.md) 方案设计5、[ADR-002](./ADR-002.md)。目前 `AppDelegate.didFinishLaunchingWithOptions` 无条件调用 `ObserverRegistrar.shared.registerAndEnableBackgroundDelivery()`：只要用户在系统弹窗里授权了 HealthKit，后台自动补全就会一直生效，用户没有关闭这个能力的入口。

用户希望把"后台自动"改成可选：设置页提供一个开关，默认关闭；首次 HealthKit 授权成功后弹一次提示，询问是否要打开，并说明之后可以随时在设置里改。

## 决策

1. **新增本地偏好 `autoSyncEnabled`**（存 `UserDefaults`，跟 `AnchorStore` 一样的轻量封装），默认值为 `false`（opt-in，不主动选择就不生效）。

2. **`AppDelegate` 只在偏好为真时才注册后台观察者**：
   ```swift
   if AutoSyncPreference().isEnabled {
       ObserverRegistrar.shared.registerAndEnableBackgroundDelivery()
   }
   ```

3. **设置页提供开关，操作实时生效，不需要重启 App**：打开时立即调用 `ObserverRegistrar.shared.registerAndEnableBackgroundDelivery()`；关闭时立即调用 `ObserverRegistrar.shared.disable()`——这个方法会做两件事：
   - 如果当前有存活的 `HKObserverQuery`，调用 `store.stop(query)` 停掉它
   - 显式调用 `HKHealthStore.disableBackgroundDelivery(for: .workoutType())` 真正撤销系统的后台投递

   第二点是关键：`enableBackgroundDelivery` 的效果是系统持久化的，不是"下次不调用就自动失效"。如果只是让 `AppDelegate` 下次不再调用 `registerAndEnableBackgroundDelivery()`，系统仍然可能在后台唤醒这个 App（即便唤醒后因为偏好是关的什么也不做），既不省电也不干净。必须显式调用 `disableBackgroundDelivery` 才能让系统真正停止为这个类型唤醒 App。

4. **首次授权成功后询问一次**：在 `RootView` 的权限请求成功之后，用另一个本地标记 `hasPrompted` 判断是否问过；没问过就弹一个**不可忽略**的 `.alert`（只有"打开"/"暂不开启"两个按钮，不能划掉/侧滑关闭），避免出现"用户没做选择、开关状态不明确"的中间态。无论选哪个，都会同时设置 `hasPrompted = true`（保证只问一次），选"打开"时立即调用注册，让效果在这次启动内就生效，不用等下次冷启动。

5. **手动"扫描历史"不受这个开关影响**，任何时候都可以用——这是现状，不需要改。

## 决策带来的影响

- 大多数用户如果在首次提示时选择"暂不开启"、之后也没去设置页手动打开，后台自动补全就不会生效，只能靠手动"扫描历史"获取新训练的距离数据。这是有意为之的 opt-in 设计，不是遗漏。
- 副作用（好的方面）：默认关闭意味着 `AppDelegate` 在 App 冷启动、用户还没做出授权/开关选择之前，不会再抢先调用 `registerAndEnableBackgroundDelivery()`——这消除了此前分析过的一个边界情况（第一次 `HKObserverQuery` 回调可能发生在权限结果确定之前）。现在只有用户明确选择打开后台自动补全，才会真正触发这条链路。
- 跟 ADR-002 的关系是正交的：ADR-002 决定"注册触发时该不该把已有历史当新数据处理"，这次决定"要不要触发注册"。两者独立生效，互不影响——不管这次注册发生在用户首次选"打开"时，还是之后在设置页手动打开时，ADR-002 里"anchor 为 nil 视为首次建立基线、不处理"的逻辑都照常适用。

## 涉及文件

- `Sources/HealthKit/AutoSyncPreference.swift`（新增）：`autoSyncEnabled`/`hasPrompted` 两个偏好
- `Sources/HealthKit/HealthStoring.swift`：协议新增 `disableBackgroundDelivery(for:)`
- `Sources/HealthKit/ObserverRegistrar.swift`：新增 `disable()` 方法
- `Sources/App/AppDelegate.swift`：改成有条件注册
- `Sources/Views/RootView.swift`：首次询问弹窗
- `Sources/Views/SettingsView.swift`：开关入口
- `Sources/Views/PermissionsView.swift`："重新请求授权"按钮里重新注册后台观察者的调用，也要判断这条偏好，跟其他调用点保持一致
