# ADR-002：后台观察者首次激活时不自动全量扫描历史

## 状态

已采纳

## 背景

参见 [PRD-001](./PRD-001.md)、[ADR-001](./ADR-001.md)。ADR-001 方案设计中，"后台自动"和"手动批量"两条触发路径都调用了同一个增量查询方法 `WorkoutQueryService.fetchNewWorkouts(anchor:using:)`，其底层依赖 `HKAnchoredObjectQuery`：`anchor` 传 `nil` 时，语义是"把当前所有匹配的数据都当作新的返回"。

`ScanViewModel`（手动扫描）每次都故意传 `nil`，要的正是这个"全量"效果。但 `ObserverRegistrar.handleUpdate()`（后台自动路径）在**第一次运行时**，本地 `AnchorStore` 还没存过任何 anchor，读出来同样是 `nil`——这导致后台路径在首次激活时，无意中复用了"全量"语义：只要 `HKObserverQuery` 建立后系统按惯例立刻回调一次 `updateHandler`（这是系统对该查询类型的固有行为，不受权限请求时机影响），就会把当时已存在的全部历史训练当作"新数据"跑一遍补全逻辑——即便用户从未点击过"扫描历史"。

这不是设计意图，而是两条路径复用同一段查询代码时，没有对"首次建立 anchor 基线"这个特殊情况做区分导致的。

## 决策

`ObserverRegistrar.handleUpdate()` 在读到本地 anchor 为 `nil` 时，视为"首次建立基线"：只保存这次查询返回的新 anchor 作为起点，**不**把这次查到的训练交给 `DistanceBackfillService` 处理。只有在本地已存在 anchor（即不是第一次运行）的后续回调中，才会真正处理查到的训练——这些才是基线建立之后真正新增的训练。

`ScanViewModel`（手动"扫描历史"）不受影响：它直接调用 `WorkoutQueryService.fetchAllWorkouts`，每次都是有意的全量扫描，不经过这个"首次跳过"的判断。

两条路径处理完之后都会把各自拿到的 anchor 写回 `AnchorStore`，共用同一份 anchor 状态：手动扫描一次之后，后台自动路径的下一次回调就只会看到这之后真正新增的训练，不会重复处理。

## 决策带来的影响

- **后台自动补全不再具备"首次激活即处理全部历史"的副作用**。用户如果从未点击过"扫描历史"，历史上已存在的训练不会被自动补全，只有该 App 开始监听之后真正新产生的训练才会被后台自动处理
- 用户想让历史训练被补全，仍然需要手动点一次"扫描历史"（这本来就是 PRD 功能需求3 里"手动批量"存在的目的）
- 这个决策与"什么时候向用户请求 HealthKit 授权"是两件独立的事，不预设授权请求的触发时机（无论是 App 启动时请求，还是延后到用户点击"扫描历史"时才请求），"首次建立基线不处理"这个逻辑在两种时机下都成立且行为一致
- 副作用：这个改动同时消除了此前评估过的一个时序风险——`AppDelegate` 在权限结果尚未确定前就会调用一次 `ObserverRegistrar.registerAndEnableBackgroundDelivery()`，原本担心这次"无权限、查到 0 条"的调用会把一个"提前污染"的 anchor 存下来，导致后续真正授权后反而漏掉历史数据。现在无论第一次回调发生在授权前还是授权后，都统一按"建立基线、不处理"对待，不再依赖具体发生时机

## 涉及文件

- `Sources/HealthKit/ObserverRegistrar.swift`：`handleUpdate()` 增加首次基线判断
- `Sources/HealthKit/AnchorStore.swift`：无需改动，行为不变
- `Sources/ViewModels/ScanViewModel.swift`：无需改动，手动扫描路径不受影响
